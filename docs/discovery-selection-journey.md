# V2 추천·선택 과정 — 구현 및 검증 범위

상품뿐 아니라 업체·브랜드·서비스를 검토한다. 관리 프로젝트 대시보드와 네이버 프로젝트에 동일한 입력 영역을 제공한다.

## 흐름

1. 대상·실제 소비자 화면 채널·측정 조건을 입력한다.
2. 알고 있는 대상 검토 → 조건 적합성 → 대안 비교 → 구매·신청 경로 예시를 준비한다. 처음 추천 단계를 선택하거나 질문을 수정할 수 있다. 최대 6단계다.
3. 실제 화면에서 입력한 질문·원본 답변·출처 URL을 순서대로 기록한다. 자동 질문 호출이나 화면 수집을 수행하는 기능은 아니다.
4. AI가 업체·브랜드 언급, 실제 추천 후보, 핵심 정보 정확성, 고객 공식 경로 연결의 판정 초안을 준비한다. 원본 변경은 거부하고, 긍정 판정의 인용은 답변에 실제 존재해야 한다. 정확성은 자동 확정하지 않는다.
5. 직원이 근거·공식 자료를 대조한 뒤 저장한다. 미확인은 null이며 실패로 집계하지 않는다. 문맥 변경 후 이전 판정은 초기화한다.
6. 최근 검토 기록 3개를 Day 0·비교·네이버 분석과 실행 초안에 연결한다. 입력 변경 감지에도 포함한다.
7. 고객 보고서 초안 반영 시 직원 판정·관찰 날짜·한계를 첨부한다. 별도 공개 승인 없이 고객에게 게시하지 않는다.

## 저장과 호환

기존 discovery_analysis_history에 Selection Journey 라운드로 저장한다. SQL 변경 불필요. 기존 채널 측정의 발견 여부를 제품 추천이나 판매처 연결로 바꾸지 않는다. 소비자 화면 채널과 API 채널을 혼동하지 않는다.

## 검증 및 남은 내용

코드 테스트·빌드와 실제 로그인 운영 검증을 구분한다. 더담다·담다트래블에서 진단→개선 과제→실제 적용→재측정→보고서를 실행하는 검증은 아직 별도 수행해야 한다. 자동 화면 수집·대화별 API 측정·예약 무인 운영은 이번 범위에 포함되지 않는다. V2 완료를 노출 성공으로 정의하지 않는다.

## 개선 과제와 후속 비교

검토를 마친 대화 이력에서 개선 과제 연결을 실행한다. 언급·추천·정보 정확성·공식 경로별로 확인되지 않은 단계를 묶고 원본 기록 ID와 질문 순서를 유지한다. 불확실한 답변은 홈페이지 결함으로 단정하지 않고 확인 과제로 제안한다. 최근 100개 대화 이력의 동일 대상·채널·조건·질문 순서·평가 항목에 연결된 과제는 중복 생성을 제외한다. 동시 요청에 대한 전역 중복 방지는 별도 범위다.

승인→실행 초안→실제 적용→재측정 검토→보고서 초안의 기존 절차를 사용한다. 후속 대화는 검토 완료, 같은 대상·채널·조건·질문 순서, 적용 이후 저장 시각을 서버에서 확인한다. 저장 시각은 실제 측정 시각의 증명이 아니므로 직원이 실제 대화도 적용 후 진행했는지 확인해야 한다. 판단 보류는 그대로 표시하고 단일 비교로 효과나 매출을 확정하지 않는다. 실제 화면 수집은 수동이며 새 대화 준비는 질문 흐름을 복사하고 답변과 판정을 비운다.

## API 답변 수집

OpenAI API와 Gemini API를 별도 채널로 제공한다. 소비자 ChatGPT·Gemini App·네이버 AI 관찰과 합치지 않는다. 단계별 인증·AI 관리 권한을 확인하고 앞선 질문·답변과 명시된 이용 조건을 보내 웹 검색 도구로 원문과 HTTP(S) 출처를 수집한다. 대상 이름을 숨겨진 추천 지시로 주입하지 않는다. 최대 6단계이며 단계당 요청 제한과 타임아웃을 적용한다. 자동 호출은 API 사용료가 발생한다.

완료된 단계는 화면에 남고 실패 시 빈 단계부터 재시도한다. 질문·조건·채널 또는 앞선 답변 변경 시 관련 답변을 초기화한다. 응답이 잘렸거나 비어 있으면 완료로 처리하지 않는다. 수집 자체는 저장·공개·개선 과제 승인하지 않으며 판정 초안과 직원 검토 후 기존 저장 절차로 진행한다. 브라우저를 닫으면 미저장 원문은 유지되지 않는다. 예약 무인 실행·영구 실행 큐·소비자 화면 자동 수집은 별도 작업이다.

## 작업 목록 정리

후속 개선 과제는 현재 작업(최대 5개), 승인·재측정 대기, 검토 후보 전체, 보류·완료 이력으로 나눠 표시한다. 현재 작업은 과거 분석의 승인/적용 과제를 유지하면서 승인→적용→최신 분석의 미승인 후보 순으로 제시한다. 이는 화면 우선순위이며 자동 승인·완료·과제 병합·삭제가 아니다. 이전 분석의 후보는 전체 탭에 남고 개수를 안내한다. 서버 조회 범위(최근 100개 분석) 내 기록을 기준으로 한다.

다음 행동과 작업 내용은 바로 보이고 긴 근거·재측정 조건·분석 재실행 도구는 펼쳐 확인한다. AI 프로젝트에서는 기존 개선 작업을 먼저 보고 새 측정·분석 도구는 별도로 펼친다. 누적 검토 후보 수를 당장 실행할 작업 수나 검색 성과로 표현하지 않는다.
