# 검색·AI와 네이버 진단 연결 (2026-10-04)

고객 목표 → 질문·검색어 → 원본 측정과 출처 → 작업 필요성 검토 → 채널별 개선 과제 → 추가 견적 후보 → 직원·고객 협의 → 실제 적용 기록 → 같은 질문·채널 재측정 → 고객 보고 초안.

- Naver 진단 이력도 기존 improvement-workflow에 연결한다. AI·네이버 서비스 선택 범위 밖의 분석을 섞지 않는다. 둘 다 선택한 고객은 AI 분석·작업 초안에 네이버 다채널 이력을 연결한다.
- 보유 채널 목록은 직원이 입력한 URL과 소유 확인 근거이다. 실제 플랫폼 인증·본문 수집·검색 노출 증명이 아니다. 미확인 블로그를 공식 계정으로 단정하지 않는다.
- 초안의 ready/needs_evidence/hold는 AI의 작업 필요성 검토 의견이다. ready는 검색 성과 증명이 아니다. 정의를 바꾸면 판단과 견적 후보를 무효화하고 다시 검토한다.
- 블로그·콘텐츠·등록·게시 작업은 실제 부족 정보와 고객 질문에 연결한 경우만 제안한다. 추가 작업명·채널·수량·작업물·완료 기준을 견적 초안에 가져오며 단가는 직원이 입력한다. 기존 계약 포함 여부와 고객 승인은 별도로 확인한다. 자동 청구·게시·공개는 하지 않는다.
- 네이버 재조회는 원본과 같은 검색어, 원본에서 정상 조회한 채널, 적용 이후 실제 checkedAt을 검증한다. 목록·새 출처 변화 초안은 업체 발견이나 AI 추천 증가를 판정한 결과가 아니다.
- 네이버 쇼핑 AI와 AI 브리핑은 실제 화면 기록 채널이다. AI가 미표시된 null은 실패로 집계하지 않는다. 답변·상품 링크·추천 이유·로그인/배송지 범위/예산/대화 조건을 기록하며 개인 주소 전체는 보관하지 않는다.
- 네이버 진단에 동일 검색어의 AI 화면 기록을 연결한다. 화면 기록이 없거나 질문이 다르면 AI 성과를 추정하지 않는다.

## 네이버 AI 접근 근거

공식 문서 확인일: 2026-10-04.

1. 네이버 쇼핑 AI는 실시간 배송·상품 스펙·리뷰·개인화 정보를 활용한다. 재측정 조건을 기록하는 이유다.
   https://navercorp.com/media/pressReleasesDetail?seq=10034666
2. CLOVA Studio는 모델·Chat Completions·임베딩 API를 제공한다. 소비자 검색·쇼핑 화면 결과를 반환하는 API로 간주하지 않는다. OpenAI 호환 API에서 web_search_options는 미지원으로 안내되어 있다.
   https://api.ncloud-docs.com/docs/clovastudio-openaicompatibility
3. RAG Reasoning은 지정한 검색 함수와 자료로 근거 기반 답변을 생성하는 기능이다. 우리 내부 분석의 선택지는 될 수 있지만 네이버 실제 추천 측정의 대체재가 아니다.
   https://api.ncloud-docs.com/docs/clovastudio-ragreasoning
4. 확인한 공개 문서에서는 소비자 AI 브리핑·쇼핑 AI 답변을 그대로 반환하는 측정용 공개 API를 확인하지 못했다. 없는 서비스라고 단정하지 않으며, 제휴·공식 이용 허용 범위가 확인되기 전 자동 측정을 표시하지 않는다.
5. 기존 NAVER Developers 쇼핑 검색 API는 2026-07-31 종료 안내가 있다. 예전 shop.json 문서를 보고 신규 연동하지 않는다. 현재 엔진의 NCP API HUB 검색·쇼핑 인사이트는 별도 경로이며 소비자 AI 답변과 다르다.
   https://developers.naver.com/notice/article/32564
   https://api.ncloud-docs.com/docs/en/naver-api-hub-search-blog

기존 테이블의 observed JSON과 measurements.channel을 활용하므로 신규 SQL은 없다. 기존 초안은 보존하며 다시 생성한 초안부터 검토 판단·견적 후보가 표시된다.
